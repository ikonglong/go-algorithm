
## 经验总结

分析 DP 问题时，最关键的步骤之一是设计状态表。通过思考下面这几个问题来驱动设计：

- 状态表单元格的值是什么，也就是有什么业务含义？
- 状态表是一维的还是二维的？每一维的业务含义是什么？大小是多少？

如果这两个问题一下子想不清楚，就先找到几个最小子问题和它们的解（最小子问题的解很容易想到），根据这几个简单例子来确定状态表的定义。

例如，爬楼梯，一次只能爬 1 阶或 2 阶。问爬完第 n 阶有多少种爬法？

我一下子想不清楚状态表应该是一维还是二维的，但觉得单元格就是爬完 x 个台阶的爬法总数。找到最小子问题，根据它们来验证下。

- 若有 0 个台阶，爬法总数 f(0) = 1
- 若只有 1 个台阶，爬法总数 f(1) = 1
- 若有 2 个台阶，爬法总数 f(2) = 2

观察这些简单例子，发现只有两个东西在变化：自变量台阶数、因变量爬法数。用一维表就可以搞定，单元格就是爬法数，下标就是台阶数
